# 13. Webhooks — уведомления во внешние системы

Webhook = «позвонить на внешний URL, когда что-то поменялось». Нужен,
когда надо:
- Построить статический сайт заново при публикации новости.
- Отправить уведомление в Slack/Telegram о новой заявке.
- Обновить поисковый индекс (Algolia / Meilisearch).
- Синхронизировать блоки в мобильное приложение.

Если у тебя **нет внешней системы** — раздел можно пропустить.

## Где это

**Сайдбар → Система → Webhooks** (`/admin/webhooks`).

## Список

```
┌─────────────────────────────────────────┐
│ 🟢 Rebuild static site                   │
│    https://example.com/hooks/rebuild    │
│    [page_blocks.updated]                 │
│    последний запуск: 19.04.2026 14:23   │
│    [Тест] [Ред.] [🗑]                    │
├─────────────────────────────────────────┤
│ ⚪ Slack notify                         │
│    https://hooks.slack.com/…             │
│    [form_submissions.created]            │
│    ни разу                               │
└─────────────────────────────────────────┘
```

- 🟢/⚪ — активен/выключен.
- URL — адрес, куда пойдёт POST.
- Бейджи — на какие события подписан.
- Время последнего успешного вызова.

## Создать

1. Нажми «**+ Новый webhook**».
2. **Название** — видно только в админке.
3. **URL** — куда слать. Должен начинаться с `https://` (для безопасности).
4. **События** — список чекбоксов, сгруппирован по таблицам. Выбери,
   на что подписать:
   - `page_blocks.created` / `updated` / `deleted`
   - `form_submissions.created`
   - и т.д. (зависит от того, что разработчик подключил).
5. **HMAC-секрет** — строка-ключ для подписи запросов (см. ниже).
   Опционально, но крайне рекомендуется для продакшна.
6. **Активен** — галочка.
7. «Сохранить».

## Что получает внешний сервер

Тело запроса — JSON:

```json
{
    "event": "page_blocks.updated",
    "delivered_at": "2026-04-19T14:23:15+00:00",
    "payload": {
        "id": 143,
        "data": {
            "page_name": "home",
            "block_key": "hero_main",
            "title": "Добро пожаловать",
            "…": "…"
        }
    }
}
```

Заголовки:

```
Content-Type: application/json
X-AdminCore-Event: page_blocks.updated
X-AdminCore-Hook-Id: 3
X-AdminCore-Signature: sha256=9f2c…a4e1
```

## Про подпись (HMAC)

Если ты указал секрет, админка подписывает каждый запрос:

```
HMAC-SHA256(body, secret)
```

Внешний сервер должен сделать то же самое со своим секретом и сравнить.
Если подписи совпали — сообщение реально от твоей админки, а не от
злоумышленника.

Пример проверки на Python:

```python
import hmac, hashlib
expected = 'sha256=' + hmac.new(
    SECRET.encode(), body, hashlib.sha256
).hexdigest()
if expected != request.headers['X-AdminCore-Signature']:
    abort(401)
```

Если **оставить секрет пустым** — заголовка `X-AdminCore-Signature` не
будет. Это риск: любой, кто знает URL, может вызывать твою систему с
фейковыми данными.

## Тестовая отправка

Кнопка «**Тест**» в списке — сразу отправляет тестовое событие
`admin.webhook_test` на URL. Используй, чтобы убедиться, что на той
стороне приняли запрос. Если вернулся 200 — будет «последний запуск:
только что». Если нет — ничего не поменяется (но событие записалось в
лог сервера).

## Если внешний сервер недоступен

Ошибка **не блокирует** редактирование — просто пишется в лог. Блок всё
равно сохранится, webhook просто пропустится. Можно проверить в
`/admin/activity`.

Если нужна гарантия «доставить хоть раз» — разработчику нужно завернуть
webhook в очередь (Laravel Queue) с ретраями. Это настраивается отдельно.

## Редактировать / удалить

Кнопки справа от каждой строки.

**При редактировании**: поле «секрет» — **оставь пустым**, если не хочешь
менять текущий. Если введёшь новый — старый затрётся.

## Частые сценарии

### Пересборка статического фронтенда

```
URL:    https://api.vercel.com/v1/integrations/deploy/prj_xxx/yyy
События: page_blocks.updated, articles.updated, articles.created
```

### Уведомления в Slack о новой заявке

Сделай в Slack «Incoming Webhook» → получишь URL.

```
URL:    https://hooks.slack.com/services/T…/B…/…
События: form_submissions.created
```

На той стороне — бот, который превратит payload в красивое сообщение.
Эту часть делает разработчик.

### Reindex в Meilisearch

```
URL:    https://your-app.example.com/api/reindex
События: page_blocks.created, page_blocks.updated, page_blocks.deleted,
         articles.created, articles.updated, articles.deleted
```
