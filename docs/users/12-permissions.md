# 12. Права доступа

Матрица «кто что может редактировать». Доступна только если на сайте
установлен `spatie/laravel-permission` (это обычно так — уточни у
разработчика).

## Где это

**Сайдбар → Система → Доступы** (`/admin/permissions`).

## Основная идея

Каждый пользователь принадлежит к **роли** (`admin`, `editor`, `manager`,
…). У каждой роли — свой набор разрешений. Разрешение = **«ресурс + действие»**:

- `articles.view` — видеть список статей.
- `articles.create` — создавать статью.
- `articles.update` — редактировать существующую.
- `articles.delete` — удалять.
- `articles.publish` — менять статус «черновик → опубликовано».

## Экран

```
┌────────────────────────────────────────────────────┐
│ Права доступа                                     │
├────────────────────────────────────────────────────┤
│ 🛡 Роль: editor                  [ Сохранить ]     │
│                                                   │
│ Образование                                       │
│   Школы       ☐ view  ☑ create  ☑ update  ☐ del  │
│   Программы   ☑ view  ☑ create  ☐ update  ☐ del  │
│   Преподав.   ☑ view  ☐ create  ☑ update  ☐ del  │
│                                                   │
│ Контент                                           │
│   Страницы    ☐ view  ☐ create  ☐ update  ☐ del  │
│   Блоки       ☑ view  ☑ create  ☑ update  ☐ del  │
└────────────────────────────────────────────────────┘
```

Для каждой роли — отдельная карточка. Внутри — таблица:
- Строки: зарегистрированные ресурсы (сгруппированы по меню-секции сайдбара).
- Колонки: действия (`view / create / update / delete / publish`).
- Ячейки: чекбокс включено/выключено.

## Быстрые действия

- Клик по **названию ресурса** — переключает все действия строки (дать
  всё / забрать всё для одного ресурса).
- Клик по **названию колонки** — переключает эту колонку для всех ресурсов
  (например, «дать этой роли просмотр всего»).
- Индивидуальный чекбокс — точечно.

## Статус «несохранённые изменения»

Когда ты тронул хоть один чекбокс — рядом с именем роли появляется
«несохранённые изменения» (жёлтая плашка), и кнопка «Сохранить» становится
активной. Пока не нажал — ничего не записалось.

## Сохранить

Сохранение идёт **отдельно для каждой роли**. То есть поменял две роли —
нажми «Сохранить» на каждой. Это защита от случайного массового
изменения.

## Какие разрешения вне матрицы

Если администратор дал пользователю какое-то нестандартное разрешение
через код (например, `billing.refund`) — оно **не показывается** в
матрице (матрица показывает только `ресурс.действие` из реестра). Но
при сохранении такие разрешения **сохраняются нетронутыми** — значит,
ты не случайно их «отзовёшь» при редактировании обычных прав.

## Как добавить новую роль

Из админки напрямую — нет. Разработчик создаёт роль через seed или
консоль:

```
Role::create(['name' => 'manager']);
```

После этого она появится в списке на экране прав.

## Как назначить пользователя в роль

Через «Сайдбар → Система → Пользователи» (`/admin/users`). На экране
пользователя — выпадающий список ролей.

Если экрана «Пользователи» нет на сайте — разработчик не подключил; надо
просить.

## Суперадмин

Роль с именем `admin` (или `super-admin`) на большинстве сайтов **игнорирует
матрицу** и имеет доступ ко всему. Это прописано в коде через Gate::before
— если видишь, что админу всё равно всё можно при снятых галочках, это
нормальное поведение.

## Частые ситуации

### «Я снял галочку view, но пользователь всё ещё видит список»

Причины:
1. Пользователь принадлежит и другой роли, у которой галочка стоит.
2. Пользователь — суперадмин.
3. Надо [сбросить кэш](./15-cache.md) (permissions кэшируются).

### «Новый ресурс не появился в матрице»

Матрица показывает только **зарегистрированные через AdminCore::resource()**.
Если разработчик добавил новый ресурс недавно — обнови страницу. Если не
появляется — разработчик забыл про регистрацию или про миграцию — спроси.

### «Хочу ограничить редактирование только своих записей»

Это сложнее, чем через матрицу. Обычно реализуется дополнительной
проверкой в Policy конкретной модели. Разработчик поможет.
