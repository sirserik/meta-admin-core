# 08. Формы и заявки

Конструктор форм: собираешь форму без кода, разработчик ставит её на сайт,
заявки приходят в админку.

## Где

**Сайдбар → Контент → Формы** (`/admin/forms`).

## Что это такое

Каждая форма — набор полей, который посетитель сайта заполняет и нажимает
«Отправить». Ответ сохраняется в базу, плюс (опционально) на почту
приходит уведомление.

Примеры форм:
- «Запись на приёмную комиссию» (ФИО, телефон, программа).
- «Обратная связь» (имя, email, сообщение).
- «Подписка на новости» (email).

## Список форм

```
┌──────────────────────────────────────────┐
│ ● Обратная связь          4 поля · 12 зая.│
│   /api/forms/contact                     │
│   Заявки   Ред.   🗑                     │
├──────────────────────────────────────────┤
│ ● Запись на приём         6 полей · 3    │
│   /api/forms/admission                   │
│   Заявки   Ред.   🗑                     │
└──────────────────────────────────────────┘
```

- 🟢 — активна (принимает заявки), ⚪ — выключена.
- «4 поля · 12 зая.» — сколько полей и сколько уже пришло заявок.
- `/api/forms/contact` — адрес, куда сайт шлёт данные. Его разработчик
  вставляет в шаблон формы на сайте.

## Создать форму

1. Нажми «**+ Новая форма**».
2. Заполни **название** (видно только в админке).
3. **Slug** — короткий латинский идентификатор. Оставь пустым → сгенерируется
   из названия (`contact-form` → `contact-form`).
4. **Уведомления на email** — адрес, куда приходит письмо при каждой
   новой заявке. Опционально.
5. **Сообщение после отправки** — что увидит посетитель. По умолчанию
   «Спасибо! Заявка принята.».
6. Добавь поля (ниже).
7. Галочка «Форма активна».
8. Сохранить.

## Редактор полей

Кнопка «**+ добавить поле**» — появляется новый пустой ряд. У поля:

- **Тип** — выпадающий список:
  - `Текст (одна строка)` — обычный `<input>`.
  - `Текст (многострочный)` — `<textarea>`.
  - `Email` — с валидацией адреса.
  - `Телефон` — с мобильной клавиатурой.
  - `URL` — с валидацией ссылки.
  - `Число`.
  - `Дата`.
  - `Выпадающий список`.
  - `Радио-кнопки`.
  - `Галочка` (checkbox).
- **Имя (name)** — латинский идентификатор (`first_name`, `email`,
  `program`). Именно по нему сайт присылает данные, и именно это попадёт
  в CSV-экспорт.
- **Подпись** — что видит посетитель над полем («Ваше имя», «Email»).
- **Placeholder** — подсказка внутри поля («Иванов Иван»).
- **Подсказка** — мелкий текст под полем («мы не рассылаем спам»).
- **Обязательное** — галочка. Без галочки поле можно пропустить.

### Варианты для `Выпадающий список` / `Радио-кнопки`

Появляется поле «Варианты» — список, **одна строка = один вариант**:

```
Маркетинг
Программирование
Дизайн
```

Или с кодом:

```
marketing=Маркетинг
programming=Программирование
design=Дизайн
```

В первом случае и значение, и подпись одинаковые («Маркетинг»). Во втором
отдельно хранится код (`marketing`), а посетитель видит «Маркетинг».

### Перестановка полей

Стрелочки ↑ / ↓ справа от поля — двигают его в списке. Порядок на сайте
совпадает с порядком в админке.

### Удалить поле

Красная иконка 🗑.

## Что происходит после сохранения

Форма сразу начинает работать — сайт может отправлять на адрес
`/api/forms/{slug}` тело с именами полей:

```json
POST /api/forms/contact
{
    "name": "Иван",
    "email": "ivan@example.com",
    "message": "Здравствуйте…"
}
```

**Валидация** — серверная. Если посетитель не заполнил обязательное поле,
сайт получит ошибку 422 и должен это отобразить.

## Просмотр заявок

Клик по «Заявки» в списке форм → страница входящих:

```
┌──────────────────────────────────────────┐
│ #12  [Новая]   19.04.2026 14:23          │
│      Имя: Иван · Email: ivan@… · …        │
│      [статус: Новая▾] [Показать] [🗑]     │
├──────────────────────────────────────────┤
│ #11  [Отвечено] 19.04.2026 11:05          │
└──────────────────────────────────────────┘
```

### Статусы

Цветной бейдж слева показывает статус:

- **🔴 Новая** — только что пришла.
- **⚪ Просмотрена** — ты её открыл.
- **🟢 Отвечено** — связался с человеком.
- **🟡 Спам** — не релевант, можно удалить позже.

Поменять статус — выпадающим списком в правой части строки.

### Показать полную заявку

Кнопка «Показать» раскрывает все поля с человеческими подписями. Полезно,
когда полей много и в свёрнутом виде не всё помещается.

### Удалить

Красная 🗑. Заявка удалится навсегда (в ревизиях не сохраняется — это
отдельная таблица).

## Экспорт в CSV

Кнопка «**CSV**» в шапке страницы заявок. Скачается файл `form-{slug}-
submissions.csv` со всеми заявками в табличном виде, удобно открывается в
Excel/Numbers (с поддержкой кириллицы).

Колонки:

| # | Когда | Статус | IP | …поля формы… |

## Уведомления на почту

Если в настройках формы указан email, при каждой новой заявке туда
отправляется письмо:

```
Тема: [Обратная связь] Новая заявка

Новая заявка через форму «Обратная связь»:

Array (
    [name] => Иван
    [email] => ivan@example.com
    [message] => Здравствуйте…
)
```

Это plain-text, без красоты. Для красиво оформленных писем — попроси
разработчика добавить кастомный шаблон.

## Антиспам

Встроенная защита:
- **Rate limiting** — один IP может отправить не больше 5 заявок в минуту.
  Превысил — увидит «попробуйте через минуту».
- **Валидация на стороне сервера** — если робот шлёт кривые данные,
  форма отклоняется.

Honeypot / CAPTCHA — не встроены, но разработчик может добавить.

## Вставить форму на сайт

После создания слаг-формы (например, `contact`) разработчик добавит в шаблон
страницы HTML-форму с POST на `/api/forms/contact`. Ты в этом не участвуешь,
но если надо что-то поменять:

- Добавь/убери поле → сохрани → разработчик обновит HTML.
- Переименовал `name` поля → разработчик тоже обновит.
- Поменял подпись / обязательность → разработчику менять не надо.

## Выключить форму

Сними галочку «Форма активна» на экране редактирования. Сайт начнёт
получать 404 на POST и должен показать ошибку.

Или выпиши форму из шаблона совсем — это уже разработчик.
