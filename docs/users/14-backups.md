# 14. Резервные копии

Кнопка «сохранить прямо сейчас» + список уже сделанных копий с возможностью
скачать.

## Где это

**Сайдбар → Система → Бэкапы** (`/admin/backup`).

## Что включает бэкап

- **База данных** (SQLite-файл или дамп MySQL/Postgres, зависит от
  сайта).
- **Медиафайлы** — всё, что в папке `storage/app/public/`.

Это один ZIP-архив с говорящим именем:
`backup-2026-04-19-143215.zip`.

## Сделать бэкап

1. Открой `/admin/backup`.
2. Нажми «**Создать бэкап**».
3. Подожди несколько секунд / минут (зависит от размера медиа).
4. В списке появится новая запись. Там же — кнопка «Скачать».

Скачанный ZIP можно хранить у себя на компьютере, облаке или передать
разработчику.

## Когда делать бэкап

- **Перед массовой правкой** — удаляешь много страниц / импортируешь
  новое меню / меняешь структуру.
- **Перед обновлением сайта** (разработчик должен знать, если обновление
  большое).
- **Раз в месяц** — на всякий случай, даже если ничего не меняется.

На большинстве серверов **ежедневный автобэкап тоже настроен** на уровне
Plesk / cron — спроси разработчика, чтобы не дублировать.

## Восстановление

Из админки — **нельзя восстановить**. Это сознательно: восстановление из
UI = слишком простой способ что-то сломать.

Если нужно откатить БД — попроси разработчика:
1. Он скачивает ZIP.
2. Распаковывает.
3. Разворачивает БД на сервере.
4. Копирует медиафайлы на место.

На большинстве случаев **ревизии (раздел 10)** — более удобный вариант,
если нужно откатить конкретную запись.

## Удалить старые бэкапы

В списке у каждой записи — красная кнопка 🗑. Удаление моментальное и
бесповоротное.

Без удаления старых — папка бэкапов растёт (один ZIP может весить 100–500
МБ). Рекомендуем держать 3–5 последних.

## Размер и ограничения

Бэкап делается **синхронно**. Если сайт большой (много медиа) и создание
занимает больше минуты — запрос может отвалиться по таймауту PHP.
В этом случае:
- Удали старые медиа, которые не используются (из `/admin/media`).
- Или попроси разработчика настроить бэкап через cron.

## Частые вопросы

### «Бэкап не скачивается, ошибка 403»

Сайт неправильно настроен или у тебя кончилось место на диске. Нужен
разработчик.

### «Почему бэкап включает только БД, без картинок?»

Возможно, на этом сайте медиа слишком много и решено хранить только БД.
Уточни настройку у разработчика.

### «Можно ли автоматизировать?»

Да — разработчик добавляет в cron Laravel Scheduler строку:

```
Schedule::command('backup:run')->daily();
```

Но из UI автозапуск не настраивается.
