# 10. История изменений (Revisions)

Каждое редактирование блока/страницы/новости сохраняет снимок прошлой
версии — это **ревизия**. Если ошиблись, удалили важное, переписали и
теперь не нравится — откатиться в один клик.

## Как попасть в историю

### Из формы редактирования

На странице правки блока в правом сайдбаре — кнопка «**История изменений**».
Клик ведёт к списку ревизий этого блока.

### Напрямую по URL

`/admin/blocks/{id}/revisions` — для блоков.
`/admin/{ресурс}/{id}/revisions` — для других ресурсов (если
интегрировано).

## Что видно

```
┌──────────────────────────────────────┐
│ История изменений                    │
│ Блок: «Hero: Добро пожаловать» #143  │
├──────────────────────────────────────┤
│ 🕐 19.04.2026 14:23:10               │
│    Иван Петров (ivan@etec.kz)        │
│             [Показать] [Восстановить] │
├──────────────────────────────────────┤
│ 🕐 18.04.2026 09:47:02               │
│    Гульнара Ахметова                 │
│             [Показать] [Восстановить] │
└──────────────────────────────────────┘
```

Список **новых сверху**. Для каждой ревизии:
- **Дата и время** когда была сделана правка.
- **Автор** — кто редактировал (email/имя). Если «система / CLI» — значит,
  правка пришла не через админку (миграция, скрипт, импорт).
- **Показать** — раскрывает JSON с полным состоянием ДО этой правки.
- **Восстановить** — применяет эту ревизию как текущую.

## Что именно сохраняется

Полное состояние **переводимых и служебных** полей записи на момент
редактирования:
- Заголовок, подзаголовок, содержимое.
- Данные блока (структурированные).
- Статус, дата публикации, активность.
- Настройки.

**Не сохраняется:**
- Прикрепление терминов (тегов/категорий) — хранится отдельно.
- Медиафайлы — если ты удалил картинку из медиатеки, она не восстановится.

## Как откатить

1. Открой историю.
2. Нажми «Показать» на нужной ревизии → посмотри, то ли это.
3. Нажми «Восстановить».
4. Подтверди.

**Текущее состояние станет новой ревизией** — то есть откат обратим. Можно
откатить откат.

## Сколько ревизий хранится

По умолчанию — **все** (без ограничений по времени или количеству).
Разработчик может включить авто-удаление старых (`$maxRevisions = 50`,
например).

## Можно ли удалить ревизию вручную?

Из UI — нет. Только разработчик через БД. Если случайно оставил там
чувствительные данные — сообщи ему.

## Ревизии для страниц, новостей, программ

Работают так же — если ресурс подключён к Revisionable. На этом сайте
пока подключён `PageBlock` (блоки). Если нужна история для других
ресурсов — попроси разработчика.

## Частые ситуации

### «Я удалил блок, а он был важный»

Блок удаляется **физически** — в ревизиях он тоже больше не виден, потому
что ревизии хранятся в связке с конкретной записью. Если запись удалена,
её ревизии тоже обычно удаляются (cascade).

**Вывод:** если сомневаешься — не удаляй, а переводи в статус «В архиве».

### «Я сохранил много раз подряд — теперь 20 ревизий на одно поле»

Ничего страшного. Одна ревизия = несколько килобайт, база не пухнет
значимо. Если мешает в списке — удалять не нужно, просто пролистай к
важной.

### «Я хочу увидеть, что именно изменилось между двумя версиями»

Сейчас diff-просмотра нет — только полный снимок. Сравнивать придётся
глазами, разворачивая «Показать» на двух ревизиях рядом (открой в двух
вкладках браузера).
